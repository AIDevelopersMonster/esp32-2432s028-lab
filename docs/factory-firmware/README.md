# Заводские демопрошивки: поиск, резервное копирование и восстановление

Этот раздел посвящён заводским и демонстрационным прошивкам для плат семейства **ESP32-2432S028 / ESP32-2432S028R (Cheap Yellow Display, CYD)** и близких ESP32-плат с дисплеем.

На заводе могут устанавливаться разные программы: тест дисплея и тачскрина, LVGL Widgets Demo, LVGL Benchmark, медиаплеер, проверка периферии, графическое меню либо демонстрация конкретного продавца. Единого универсального `factory.bin` для всех плат не существует.

> **Главное правило:** до первой собственной прошивки сохраните полный образ flash-памяти именно своей платы, считайте его дважды и сравните SHA-256.

## Почему нельзя записывать первый найденный BIN

Даже платы с одинаковым названием могут отличаться:

- типом тачскрина: резистивный XPT2046 или ёмкостный контроллер;
- контроллером дисплея и его инициализацией;
- распиновкой SPI, подсветки, SD-карты, RGB LED и аудио;
- объёмом flash-памяти;
- таблицей разделов;
- ориентацией и цветовым порядком дисплея;
- версией аппаратной ревизии;
- настройками Secure Boot или Flash Encryption.

Неподходящий образ обычно не повреждает ESP32 необратимо, но плата может не загрузиться, показать белый экран или потерять заводские настройки. Настоящая опасность возникает при работе с eFuse, защищёнными устройствами и принудительном стирании зашифрованной flash.

## Что именно называют заводской прошивкой

### 1. Полный дамп flash

Файл размером, равным всей микросхеме flash, например 4, 8 или 16 МБ. Обычно он начинается с адреса `0x0` и содержит загрузчик, таблицу разделов, приложение, NVS и файловую систему.

Пример:

```text
ESP32-2432S028R_factory_full_4MB.bin
```

Это лучший вариант для точного восстановления конкретного экземпляра платы.

### 2. Объединённый образ

Один BIN, созданный из нескольких частей командой `merge-bin`. Его часто записывают с `0x0`, но адрес должен быть указан автором сборки.

### 3. Набор отдельных BIN-файлов

Типичный комплект:

```text
bootloader.bin
partitions.bin
boot_app0.bin
firmware.bin
```

Каждый файл записывается по своему адресу. Нельзя угадывать адреса: используйте инструкцию автора или строку загрузки из PlatformIO/Arduino/ESP-IDF.

### 4. Только приложение

Файл `firmware.bin` размером от нескольких сотен килобайт до нескольких мегабайт часто является только приложением. Для классического Arduino-ESP32 его нередко пишут с `0x10000`, но это не универсальное правило.

## Где искать готовые прошивки

1. На странице продавца платы: разделы **Download**, **Resources**, **Factory firmware**, **Burning files**, **Demo**, **资料下载**.
2. В архиве, приложенном к карточке товара.
3. В GitHub Releases и каталогах `firmware/`, `bin/`, `factory/`, `release/`, `build/`.
4. В документации производителя или сборщика платы.
5. В сообществах CYD, но только при наличии точного обозначения ревизии, фотографии платы, контрольной суммы и инструкции записи.

Рекомендуемые поисковые запросы:

```text

Cheap Yellow Display factory firmware

```

Каталог известных вариантов и источников находится в [`FIRMWARE-CATALOG.md`](FIRMWARE-CATALOG.md).

# Пошаговая дорожная карта

## Этап 0. Зафиксировать точную плату

До подключения сфотографируйте обе стороны платы и запишите:

- полную маркировку на текстолите;
- букву ревизии, например `R` или `C`;
- маркировку ESP32-модуля;
- маркировку микросхемы flash, если видна;
- тип USB-UART;
- надписи возле разъёмов;
- внешний вид заводской демонстрации.

Создайте отдельный каталог экземпляра:

```text
backups/
└── ESP32-2432S028R_board-01/
    ├── photos/
    ├── logs/
    ├── hashes/
    └── images/
```

## Этап 1. Установить esptool

```bash
python -m pip install --upgrade esptool
python -m esptool version
```

В esptool 5 используются команды с дефисами: `read-flash`, `write-flash`, `flash-id`. Старые инструкции могут использовать `read_flash`, `write_flash`, `flash_id`.

Официальная документация:

- <https://docs.espressif.com/projects/esptool/en/latest/esp32/esptool/basic-commands.html>
- <https://docs.espressif.com/projects/esptool/en/latest/esp32/esptool/flashing-firmware.html>

## Этап 2. Найти последовательный порт

Windows: откройте диспетчер устройств и найдите новый `COM`-порт.

Linux:

```bash
ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
```

Подключайте плату кабелем с передачей данных. Закройте Serial Monitor, PlatformIO Monitor и другие программы, занявшие порт.

В примерах ниже используется `COM5`. Замените его своим портом.

## Этап 3. Проверить связь без изменения flash

```bash
python -m esptool --chip esp32 --port COM5 chip-id
python -m esptool --chip esp32 --port COM5 flash-id
```

Сохраните вывод в журнал:

```bash
python -m esptool --chip esp32 --port COM5 flash-id > logs/flash-id.txt 2>&1
```

Если соединение не устанавливается:

1. удерживайте `BOOT`;
2. кратко нажмите `RESET/EN`;
3. запустите команду;
4. отпустите `BOOT` после появления `Connecting...`.

## Этап 4. Проверить защитные eFuse

```bash
python -m espefuse --chip esp32 --port COM5 summary
```

Сохраните отчёт:

```bash
python -m espefuse --chip esp32 --port COM5 summary > logs/efuse-summary.txt 2>&1
```

Проверьте признаки Flash Encryption, Secure Boot и ограничений режима загрузки. Для классического ESP32 обращают внимание на поля вроде `FLASH_CRYPT_CNT`, `ABS_DONE_0`, `ABS_DONE_1`, `DISABLE_DL_DECRYPT`, `DISABLE_DL_ENCRYPT` и `DISABLE_DL_CACHE`.

> Не записывайте и не изменяйте eFuse. Многие eFuse одноразовые и необратимые.

Если esptool сообщает об активном Secure Boot или Flash Encryption, не используйте `--force`, пока не понятна конфигурация устройства.

## Этап 5. Проверить возможность чтения малым безопасным тестом

```bash
python -m esptool --chip esp32 --port COM5 read-flash 0x0 0x1000 images/read-test-1.bin
python -m esptool --chip esp32 --port COM5 read-flash 0x0 0x1000 images/read-test-2.bin
```

Windows:

```bat
certutil -hashfile images\read-test-1.bin SHA256
certutil -hashfile images\read-test-2.bin SHA256
```

Linux/macOS:

```bash
sha256sum images/read-test-1.bin images/read-test-2.bin
```

Обе суммы должны совпасть. Этот этап ничего не стирает и не записывает.

## Этап 6. Определить объём flash

Команда `flash-id` обычно выводит, например:

```text
Detected flash size: 4 MB
```

Соответствия:

| Flash | Размер чтения |
|---:|---:|
| 2 МБ | `0x200000` |
| 4 МБ | `0x400000` |
| 8 МБ | `0x800000` |
| 16 МБ | `0x1000000` |

В современных версиях esptool можно использовать автоматическое определение:

```bash
python -m esptool --chip esp32 --port COM5 read-flash 0 ALL images/factory-full.bin
```

## Этап 7. Считать полный образ дважды

Автоматический размер:

```bash
python -m esptool --chip esp32 --port COM5 --baud 460800 read-flash 0 ALL images/factory-read-1.bin
python -m esptool --chip esp32 --port COM5 --baud 460800 read-flash 0 ALL images/factory-read-2.bin
```

Либо явно для 4 МБ:

```bash
python -m esptool --chip esp32 --port COM5 --baud 460800 read-flash 0x0 0x400000 images/factory-read-1.bin
python -m esptool --chip esp32 --port COM5 --baud 460800 read-flash 0x0 0x400000 images/factory-read-2.bin
```

При нестабильной связи уменьшите скорость до `115200`.

## Этап 8. Проверить резервную копию

Windows:

```bat
certutil -hashfile images\factory-read-1.bin SHA256 > hashes\factory-read-1.sha256.txt
certutil -hashfile images\factory-read-2.bin SHA256 > hashes\factory-read-2.sha256.txt
```

Linux/macOS:

```bash
sha256sum images/factory-read-1.bin > hashes/factory-read-1.sha256
sha256sum images/factory-read-2.bin > hashes/factory-read-2.sha256
cmp images/factory-read-1.bin images/factory-read-2.bin
```

Критерий PASS:

- размеры файлов совпадают с размером flash;
- SHA-256 двух чтений одинаков;
- `cmp` не сообщает различий;
- заводская демонстрация после перезагрузки продолжает работать.

После проверки переименуйте первую копию, например:

```text
ESP32-2432S028R_board-01_factory_original_4MB.bin
```

Храните минимум две копии на разных носителях.

## Этап 9. Проверить скачанный образ до записи

Для каждого скачанного файла зафиксируйте:

- URL источника;
- дату скачивания;
- название платы и ревизии;
- размер файла;
- SHA-256;
- предполагаемый адрес записи;
- тип файла: полный дамп, merged image, приложение или отдельная часть;
- лицензию и разрешение на распространение.

Команды:

```bash
python -m esptool image-info downloaded.bin
```

Windows:

```bat
certutil -hashfile downloaded.bin SHA256
```

Linux/macOS:

```bash
sha256sum downloaded.bin
```

Красные флаги:

- отсутствует точная модель платы;
- нет адреса записи;
- архив требует отключить защиту или применить `--force`;
- файл выложен без источника и контрольной суммы;
- размер полного образа превышает физический размер flash;
- образ предназначен для другого семейства ESP32;
- продавец смешал инструкции для нескольких ревизий.

## Этап 10. Пробная запись только после резервного копирования

### Полный образ, предназначенный для адреса `0x0`

```bash
python -m esptool --chip esp32 --port COM5 erase-flash
python -m esptool --chip esp32 --port COM5 --baud 460800 write-flash 0x0 downloaded-full.bin
```

### Набор отдельных файлов

Пример, а не универсальная схема:

```bash
python -m esptool --chip esp32 --port COM5 --baud 460800 write-flash \
  0x1000 bootloader.bin \
  0x8000 partitions.bin \
  0xE000 boot_app0.bin \
  0x10000 firmware.bin
```

Используйте адреса только из документации конкретной сборки. Официальная документация esptool прямо требует передавать пары `адрес + файл` и брать смещения из SDK или проекта.

## Этап 11. Проверить запись

`write-flash` выполняет проверку записанных данных. Дополнительно можно выполнить:

```bash
python -m esptool --chip esp32 --port COM5 verify-flash 0x0 downloaded-full.bin
```

Или считать образ обратно:

```bash
python -m esptool --chip esp32 --port COM5 read-flash 0 ALL images/after-write.bin
```

После первого запуска NVS и файловая система могут измениться, поэтому побайтовое сравнение полного дампа лучше делать сразу после записи.

## Этап 12. Проверить функции платы

После перезагрузки проверьте:

- запуск без циклического reset;
- изображение и ориентацию;
- цвета;
- подсветку;
- тачскрин по всей площади;
- microSD;
- RGB LED;
- Wi-Fi/Bluetooth, если используются;
- звук и внешние разъёмы;
- сообщения UART на скорости, указанной автором прошивки.

Белый экран при работающем UART чаще говорит о несовпадении контроллера дисплея, распиновки или подсветки, а не о неисправности ESP32.

## Этап 13. Восстановить заводской образ

```bash
python -m esptool --chip esp32 --port COM5 erase-flash
python -m esptool --chip esp32 --port COM5 --baud 460800 write-flash 0x0 ESP32-2432S028R_board-01_factory_original_4MB.bin
```

После записи нажмите `RESET` или переподключите питание.

Если исходный образ был считан с устройства с Flash Encryption, перенос на другой экземпляр платы может не работать. Такой дамп следует считать привязанным к исходному устройству, пока не доказано обратное.

```text
[ ] Источник скачанного BIN зафиксирован
[ ] Тип BIN и адрес записи подтверждены
[ ] Прошивка соответствует контроллеру дисплея и тачскрина
[ ] Запись проверена

```

## Что не следует публиковать без проверки

Полный дамп может содержать:

- Wi-Fi credentials;
- токены и API-ключи;
- уникальные настройки NVS;
- сертификаты;
- серийные номера;
- проприетарные ресурсы производителя.

Перед публикацией чужой заводской прошивки проверьте лицензию и удалите персональные или секретные данные. Безопаснее публиковать ссылку на первоисточник, SHA-256 и инструкцию, а не перезаливать бинарный файл.
