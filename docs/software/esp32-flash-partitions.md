# Разметка Flash-памяти ESP32

Flash ESP32 обычно разбита на отдельные области. Часть из них находится до таблицы разделов, а остальные описываются самой таблицей разделов.

> Важно: приведённые ниже адреса являются типовой схемой ESP-IDF, а не подтверждённой разметкой конкретной ESP32-2432S028. Точную карту нужно извлечь из её `partition-table.bin` или полного дампа.

## Общая структура

```text
0x000000  ┌────────────────────────────────────┐
          │ начальная/резервная область         │
0x001000  ├────────────────────────────────────┤
          │ bootloader                          │
          │ размер зависит от сборки            │
0x008000  ├────────────────────────────────────┤
          │ таблица разделов                    │
          │ обычно сектор 0x1000 байт           │
0x009000  ├────────────────────────────────────┤
          │ разделы data                        │
          │ NVS, OTA data, PHY и другие         │
0x010000  ├────────────────────────────────────┤
          │ application: factory или OTA        │
          │ точный размер берётся из таблицы    │
          ├────────────────────────────────────┤
          │ дополнительные app/data-разделы     │
          │ SPIFFS, FAT, LittleFS, coredump...  │
0x400000  └────────────────────────────────────┘
          конец Flash 4 MB
```

## Что находится до таблицы разделов

### Область `0x0000–0x0FFF`

На классическом ESP32 часто не содержит основной прошивки. В исследуемой плате два чтения этой области дали только `0xFF`.

### Bootloader

Bootloader обычно начинается с `0x1000`. Он:

- инициализирует Flash;
- читает таблицу разделов;
- выбирает application-раздел;
- запускает приложение.

Bootloader не следует путать с основным приложением.

### Таблица разделов

Стандартный offset ESP-IDF — `0x8000`. Таблица занимает один сектор Flash размером `0x1000` байт, хотя полезная область таблицы меньше. Offset может быть изменён при сборке проекта.

Каждая запись содержит:

- имя (`label`);
- тип;
- подтип;
- начальный адрес (`offset`);
- размер;
- флаги.

## Основные типы разделов

### `app`

Содержит исполняемую программу.

Распространённые подтипы:

| Подтип | Назначение |
|---|---|
| `factory` | основное заводское приложение |
| `ota_0` | первый OTA-слот |
| `ota_1` | второй OTA-слот |
| `test` | тестовое приложение |

Application-разделы должны начинаться с адресов, кратных `0x10000` — 64 КБ.

### `data`

Содержит данные, настройки или файловые системы.

| Подтип/имя | Назначение | Обычно изменяется при работе |
|---|---|---|
| `nvs` | настройки, ключи, переменные приложения | да |
| `otadata` | выбор активного OTA-приложения | да |
| `phy_init` | данные инициализации радиотракта | обычно редко |
| `nvs_keys` | ключи зашифрованного NVS | зависит от проекта |
| `coredump` | аварийный дамп | да |
| `spiffs` | файловая система SPIFFS | возможно |
| `fat` | FAT-файловая система | возможно |
| `littlefs` | LittleFS, часто как пользовательский subtype | возможно |

Обычные data-разделы выравниваются по сектору `0x1000` — 4 КБ.

## Типовая схема без OTA

Это пример встроенной таблицы ESP-IDF, а не карта нашей платы:

```text
# Name,    Type, SubType, Offset,   Size
nvs,       data, nvs,     0x9000,   0x6000
phy_init,  data, phy,     0xF000,   0x1000
factory,   app,  factory, 0x10000,  1M
```

## Типовая схема с factory и двумя OTA-слотами

```text
# Name,    Type, SubType, Offset,    Size
nvs,       data, nvs,     0x9000,    0x4000
otadata,   data, ota,     0xD000,    0x2000
phy_init,  data, phy,     0xF000,    0x1000
factory,   app,  factory, 0x10000,   1M
ota_0,     app,  ota_0,   0x110000,  1M
ota_1,     app,  ota_1,   0x210000,  1M
```

На плате с 4 MB после этих разделов может оставаться свободная область или находиться дополнительный data-раздел.

## Как получить точную карту нашей платы

### 1. Считать таблицу разделов

```powershell
python -m esptool --chip esp32 --port COM12 read-flash 0x8000 0x1000 partition-table.bin
```

Эта команда ничего не записывает во Flash.

### 2. Проверить хэш

```powershell
(Get-FileHash .\partition-table.bin -Algorithm SHA256).Hash
```

### 3. Декодировать таблицу

В установленном ESP-IDF используется `gen_esp32part.py`. Типовая команда из каталога ESP-IDF:

```powershell
python .\components\partition_table\gen_esp32part.py partition-table.bin
```

Утилита выведет CSV-подобную таблицу с реальными именами, адресами и размерами.

## Как вырезать конкретный раздел из полного дампа

После определения `offset` и `size` можно извлечь раздел повторным чтением с платы:

```powershell
python -m esptool --chip esp32 --port COM12 read-flash OFFSET SIZE partition-name.bin
```

Пример только для условного приложения по адресу `0x10000` размером `0x140000`:

```powershell
python -m esptool --chip esp32 --port COM12 read-flash 0x10000 0x140000 factory-app.bin
```

Адрес и размер нельзя брать из примера — только из декодированной таблицы конкретной платы.

## Что сравнивать с другой заводской прошивкой

Наиболее полезно сравнивать отдельно:

- bootloader;
- таблицу разделов;
- application-раздел;
- неизменяемый файловый раздел.

Полные дампы разных экземпляров могут иметь разные SHA-256 из-за содержимого `nvs`, `otadata`, файловой системы, счётчиков и других изменяемых данных.

## Паспорт разметки конкретной платы

После декодирования сохранить результат в таком виде:

```text
Board: ESP32-2432S028...
PCB revision:
Flash size: 0x400000
Partition-table offset:
Partition-table SHA-256:

Name       Type   SubType   Offset      Size        Mutable
---------  -----  --------  ----------  ----------  -------
...
```
