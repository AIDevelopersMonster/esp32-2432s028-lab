# Полный резервный дамп Flash в Windows

Этот этап выполняется после успешных команд `chip-id`, `flash-id` и двух совпадающих тестовых чтений.

## Что считывать

Для резервной копии нужно читать **всю Flash целиком**, начиная с адреса `0x0`, а не только область выше bootloader.

Полный образ должен включать:

- пустую или служебную область `0x0000–0x0FFF`;
- bootloader;
- таблицу разделов;
- NVS и другие служебные разделы;
- factory/OTA application;
- SPIFFS, LittleFS, FAT или другие файловые разделы;
- оставшиеся данные до конца Flash.

Для обнаруженной Flash 4 MB полный размер равен:

```text
0x400000 = 4194304 bytes
```

## Два независимых полных чтения

```powershell
python -m esptool --chip esp32 --port COM12 --baud 460800 read-flash 0x0 0x400000 esp32-2432s028-full-1.bin
python -m esptool --chip esp32 --port COM12 --baud 460800 read-flash 0x0 0x400000 esp32-2432s028-full-2.bin
```

Вместо явного размера esptool также допускает автоматическое определение:

```powershell
python -m esptool --chip esp32 --port COM12 --baud 460800 read-flash 0 ALL esp32-2432s028-full-1.bin
```

Для повторяемости в данном паспорте используется явный размер `0x400000`, уже подтверждённый командой `flash-id`.

Если на скорости `460800` возникают ошибки, повторить чтение на `115200`.

## Проверка размеров

```powershell
Get-Item .\esp32-2432s028-full-1.bin, .\esp32-2432s028-full-2.bin | Select-Object Name, Length
```

Ожидаемый размер каждого файла:

```text
4194304
```

## Проверка SHA-256

```powershell
(Get-FileHash .\esp32-2432s028-full-1.bin -Algorithm SHA256).Hash
(Get-FileHash .\esp32-2432s028-full-2.bin -Algorithm SHA256).Hash
```

Логическая проверка:

```powershell
(Get-FileHash .\esp32-2432s028-full-1.bin -Algorithm SHA256).Hash -eq (Get-FileHash .\esp32-2432s028-full-2.bin -Algorithm SHA256).Hash
```

Ожидаемый результат:

```text
True
```

Дополнительное побайтовое сравнение:

```powershell
cmd /c fc /b esp32-2432s028-full-1.bin esp32-2432s028-full-2.bin
```

## Почему нельзя ориентироваться только на хэш похожей прошивки

Полный дамп другой платы может отличаться даже при той же заводской программе. Причины:

- NVS содержит настройки и переменные;
- могут присутствовать Wi-Fi данные, счётчики и состояние приложения;
- OTA data меняется при обновлениях;
- файловая система может содержать уникальные файлы;
- некоторые разделы заполняются при первом запуске;
- продавец мог использовать другую сборку или таблицу разделов.

Поэтому главный контроль целостности — совпадение **двух независимо считанных дампов одной платы**.

## Что можно сравнивать с найденной заводской прошивкой

Для точного сравнения сторонний образ должен соответствовать:

- той же маркировке PCB;
- той же аппаратной ревизии;
- тому же типу сенсора R/C;
- тому же объёму Flash;
- той же заводской версии программы.

Сравнивать лучше по отдельным областям:

1. bootloader;
2. таблица разделов;
3. factory/OTA application;
4. неизменяемая файловая система, если она есть.

Не следует ожидать совпадения NVS, OTA data и других изменяемых разделов.

## Чтение таблицы разделов

Для классического ESP32 стандартный адрес таблицы разделов — `0x8000`, размер сектора — `0x1000`. Но адрес может быть изменён в проекте, поэтому это сначала проверяется по содержимому.

```powershell
python -m esptool --chip esp32 --port COM12 read-flash 0x8000 0x1000 partition-table.bin
```

После установки ESP-IDF таблицу можно вывести утилитой `gen_esp32part.py`:

```powershell
python gen_esp32part.py partition-table.bin
```

Она покажет реальные имена, адреса и размеры разделов. Только после этого следует вырезать application-раздел для сравнения.

## Поиск похожей заводской прошивки

Искать следует не просто `ESP32-2432S028 firmware`, а точную комбинацию:

```text
маркировка PCB + ревизия + R/C + factory demo
```

Приоритет источников:

1. архив производителя или продавца;
2. Guition / Jingcai / JCZN1688;
3. дамп платы той же ревизии с известным происхождением;
4. проверенный community archive.

Для каждого найденного файла сохранить URL, размер, SHA-256, дату скачивания и заявленные адреса записи.

## Стоп-условие

До получения двух совпадающих полных дампов запрещено выполнять:

```text
erase-flash
write-flash
erase-region
```

Полный дамп следует хранить минимум в двух независимых местах. Не публиковать его без проверки на пароли, токены, сетевые настройки и персональные данные.
