# 03B — Лаборатория чтения и записи microSD

Файл программы: [`03_sd_rw_lab.ino`](03_sd_rw_lab.ino)

Этот пример дополняет [`03_sd_test`](../03_sd_test/README.md).

`03_sd_test` безопасно проверяет подключение карты, её размер и чтение каталога. `03_sd_rw_lab` показывает уже практическую работу с файловой системой: создание каталогов и подкаталогов, запись, повторное открытие, проверку прочитанного содержимого и добавление данных в существующий файл.

## Что делает скетч

Скетч работает только внутри собственного каталога:

```
/cyd_lab
```

Он создаёт такую структуру:

```
/cyd_lab
├── readme.txt
├── config
│   └── device.txt
├── logs
│   └── session.txt
└── archive
    └── 2026
        └── result.txt
```

После создания структуры скетч:

1. создаёт каталоги;
2. создаёт несколько файлов на разных уровнях;
3. записывает заранее известные строки;
4. закрывает каждый файл;
5. снова открывает его на чтение;
6. сравнивает реально прочитанное содержимое с ожидаемым;
7. дописывает строку в `/cyd_lab/logs/session.txt`;
8. снова проверяет содержимое после append;
9. печатает всё дерево `/cyd_lab` в Serial Monitor;
10. оставляет созданные файлы на карте, чтобы их можно было посмотреть на компьютере.

## Безопасность

Этот пример **не форматирует microSD**.

Он не должен изменять существующие файлы вне:

```
/cyd_lab
```

Но файлы с теми же именами внутри `/cyd_lab` используются лабораторией повторно. Поэтому не храните важные пользовательские данные в каталоге `/cyd_lab`.

## Требования

Перед этим примером рекомендуется успешно выполнить:

- [`03_sd_test`](../03_sd_test/README.md);
- установку [`CYD_Board`](../../libraries/CYD_Board/README.md).

Используются стандартные библиотеки ESP32 Arduino Core:

```
SPI
SD
```

Дополнительные библиотеки устанавливать не нужно.

## Выводы microSD

| Сигнал | GPIO |
|---|---:|
| MISO | 19 |
| MOSI | 23 |
| SCLK | 18 |
| CS | 5 |

Они берутся из `CYD_Board`.

## Запуск

1. Вставьте microSD при отключённом питании платы.
2. Откройте [`03_sd_rw_lab.ino`](03_sd_rw_lab.ino).
3. Нажмите **Verify**.
4. Нажмите **Upload**.
5. Откройте Serial Monitor.
6. Установите скорость:

```
115200 baud
```

7. Если начало вывода пропущено, нажмите RESET/EN один раз.

## Ожидаемый ход теста

Сначала должна успешно определиться карта, например:

```
Card size: 30250 MB
```

Затем появятся сообщения о каталогах:

```
DIR CREATED: /cyd_lab
DIR CREATED: /cyd_lab/config
DIR CREATED: /cyd_lab/logs
DIR CREATED: /cyd_lab/archive
DIR CREATED: /cyd_lab/archive/2026
```

При повторном запуске часть строк может выглядеть так:

```
DIR EXISTS : /cyd_lab
```

Это нормально.

Для файлов ожидаются сообщения наподобие:

```
WRITE      : /cyd_lab/readme.txt
  PASS: ... bytes written and verified
```

и:

```
APPEND     : /cyd_lab/logs/session.txt
  PASS: append verified
```

В конце должен появиться итог:

```
SD_RW_LAB_PASS
DIRECTORY_CREATE_CONFIRMED
NESTED_DIRECTORY_CONFIRMED
FILE_WRITE_CONFIRMED
FILE_READBACK_CONFIRMED
FILE_APPEND_CONFIRMED
```

## Что можно проверить на компьютере после теста

Выключите питание платы, извлеките карту и откройте её на компьютере.

В `/cyd_lab` должны остаться созданные каталоги и файлы. Например файл:

```
/cyd_lab/config/device.txt
```

должен содержать:

```
board=ESP32-2432S028R
mode=sd-rw-lab
```

А:

```
/cyd_lab/logs/session.txt
```

должен содержать две строки:

```
session-start
write-read-verified
```

Это даёт наглядное подтверждение, что ESP32 не только видит карту, но и реально создаёт структуру файловой системы, записывает и повторно читает данные.

## Что этот пример намеренно не делает

Лаборатория не проверяет:

- форматирование карты;
- удаление пользовательских каталогов;
- устойчивость к внезапному отключению питания во время записи;
- производительность большими блоками;
- износ карты;
- одновременную работу SD, TFT и XPT2046.

Форматирование следует держать отдельной сервисной операцией, потому что оно уничтожает данные на карте.
